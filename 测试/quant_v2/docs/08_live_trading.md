# Quant V2 实盘运维（V3 规划）

> **状态声明**：本文档内容以 V3 规划为主，**V2 未实现实盘能力**。请勿把本文当已交付功能。落地前需逐条核对代码。

## 0. 现状差距（回测 → 实盘）

| 项 | 回测已支持 | 实盘需要（V3） |
|---|---|---|
| 数据 | 日线 Bar | 实时行情/Tick、历史对齐校验 |
| 成交 | 撮合器近似 | 券商/交易所真实撮合 |
| 费用 | 模型近似 | 真实交割单 |
| 时钟 | 回测时钟 | 实盘时钟+交易日历 |
| 对账 | — | 本地流水 vs 券商流水核对 |
| 风控 | 预下单校验 | 实时 + 强平/熔断 |
| 安全 | — | API 凭据管理、权限隔离 |

## 1. 实盘模块设计蓝图（目录建议）

```
live/                    # （新建，V3）
  gateway/               # 券商网关适配（同花顺/掘金/中泰XtQuant等）
    base_gateway.py      # 抽象：connect/submit/cancel/query
    gateway_registry.py  # 网关注册与选择

  monitor/               # 监控告警（持仓/现金/委托异常）
```

## 2. 网关抽象（统一实盘接入）

所有券商网关实现统一接口，切换券商不改业务代码：

```python
class BaseLiveGateway(ABC):
    def connect(self, credentials): ...
    def submit_order(self, order) -> str          # 返回交易所委托号
    def cancel_order(self, client_order_id): ...
    def query_order(self, exchange_order_id) -> OrderStatus
    def query_position(self, symbol) -> Position
    def query_account(self) -> AccountSnapshot
    # 事件回调
    def on_order_update(self, cb): ...
    def on_trade_fill(self, cb): ...
    def on_tick(self, cb): ...
```

候选网关：GM 掘金（`gm`）、同花顺、中泰 XtQuant。适配各自 SDK。

## 3. 对账机制（Reconciliation）——实盘资金安全核心

**目标**：本地模拟撮合的流水，必须与券商真实流水核对一致，避免“本地以为成交、实际未成交”的错单。

对账维度：
1. **现金对账**：本地 `account.cash` vs 券商可用资金，偏差容忍内（如 <1 元）视为一致。
2. **持仓对账**：逐标的核对 `qty / 可用 / 冻结 / 成本`。
3. **流水对账**：本地 `Trade` vs 券商成交回报，按 `order_id`（映射到交易所委托号）逐笔匹配。
4. **逐日核对**：每日收盘后跑一次，留存核对记录（`persistence/`）。

异常处理：出现不一致 → 暂停发单、告警、人工介入，**禁止自动补单**。

## 4. 实盘风控（相比回测增强）

- **盘前**：配置校验、连接健康检查、交易日历核对。
- **盘中实时**：价格偏离、单笔/单日限额、净值回撤、持仓集中度；超标即**告警/断路器**，触发可配置（仅告警 / 拒新单 / 全平）。
- **强平**：V2 的 `StopManager` 回测止损 → V3 需真实撤单+下平仓单，注意券商单笔限制与追单。

## 5. 监控告警（建议指标）

| 类别 | 渠道 | 告警示例 |
|---|---|---|
| 系统 | 邮件/IM | 网关断连、行情源无数据、进程存活 |
| 交易 | 邮件/IM | 委托拒单、长时间未成交、成交/撤单异常 |
| 对账 | 邮件/IM + 记录 | 现金/持仓/流水不一致 |
| 风控 | 即时强告警 | 触发风控限额、回撤超阈值 |

## 6. 安全与合规底线（无论 V3 落地与否都须遵守）

- **API 凭据**：存 `SECRET`/环境变量/加密配置，**禁止硬编码进代码或提交到 Git**。
- **最小权限**：行情只读账号与交易账号分离；实盘账号禁用第三方脚本直连，一律走受控网关。
- **不可逆操作确认**：实盘下单、撤单、强平属高影响操作，执行前须人工确认。
- **记录留痕**：所有发单/撤单/对账留日志与账本，便于审计与回放。
- **回测≠实盘承诺**：本文档强调回测理想化假设（见 `docs/03`），实盘收益不可由回测外推保证。

## 7. 建议落地顺序

1. 网关抽象 + GM/同花顺适配（先一只账号只读）
2. 实盘订单管理 + 委托状态机
3. 对账器（先现金+持仓）
4. 实时风控 + 断路器
5. 监控告警 + 每日核对
6. 灰度：小资金模拟切换 → 实盘
